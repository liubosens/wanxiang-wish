# 万象祈愿 · 升星 / 战力 规格（Phase 4 设计闸门 · design-strategist 交付）

> gdd-03（保留引擎）+ gdd-05（竞争层）的养成与战力定义。数值 [PLACEHOLDER] 待校准。

## 1. 升星模型
- `inventory[itemId]` 增加字段 `star`（0–5，默认 0）。
- 升星成本（升到 s+1 星）：
  - `fragments = 10 × (s+1) × rarMult`
  - `rarMult`：R=1，SR=2，UR=3
  - 当目标星 `≥ 3` 时**额外**消耗 `stone = (s+1-2) × rarMult`（进阶石）
- 重复卡转化碎片规则沿用现有 `draw-api`：`R→5`、`SR→30`、`UR→80`（[PLACEHOLDER] 建议值）。
- 进阶石（stone）来源 [PLACEHOLDER]：试炼奖励 / 排行榜·PK 胜利奖励 / 每日小额。需在 `cloudfunctions` 新增产出点。

## 2. 战力公式
```
战力(power) = Σ_{编队最优 5 张已拥有卡}  rarWeight[rarity] × (1 + 0.25 × star)
rarWeight: R=10, SR=30, UR=80   （[PLACEHOLDER] 建议值，需平衡测试）
```
- 编队 = 自动取战力最高的 5 张（MVP 不做手动编队；[PLACEHOLDER] 后续可开放手动）。
- 战力仅在抽卡/升星后变化 → 驱动排行榜排名（gdd-05）。

## 3. 图鉴完成度口径
- 按世界分两档（gdd-03）：
  - **阶段完成** = 该世界 R+SR 收集数 / R+SR 总数
  - **终极目标** = 该世界 UR 收集数 / UR 总数（UR 仅硬保底/兑换，作为长线追逐）
- 总图鉴% = 全部已拥有卡 / 全部卡（含 UR）。

## 4. 客户端 vs 服务端职责
- 战力由客户端按公式算，抽卡/升星后上报 `users.power`（云函数写入，防篡改可改由云重算）。
- 升星动作需服务端校验资源（防本地篡改）→ 新增云函数 `upgrade` 或并入 `draw` 同套事务。

## 5. 风险
- 进阶石若来源不足 → 升星卡在 3 星 → 战力天花板 → 排行榜通胀停滞。需在 v0.5 验证期监控进阶石存量中位数。
