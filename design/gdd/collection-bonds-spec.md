# 万象祈愿 · 图鉴羁绊组合 规格（Phase 5 拓展 · design-strategist 交付）

> 同世界指定卡组合 → 战力加成。战力第二增长轴 + 冷门卡价值抢救。
> 羁绊数值全部 [PLACEHOLDER]，总加成上限与升星 0.25/星 的量级对齐后校准。

## 1. 机制定义

- **激活条件**：组合内所有卡均为"已拥有"（`inventory[id].count > 0`），与星级无关。
- **效果**：全局战力加成，多个羁绊**加算后一次性外乘**（见 §3）。
- **展示**：图鉴页按世界分 tab 列羁绊清单；激活态高亮，未激活显示剪影 + 缺卡数。
- 羁绊一旦激活即永久生效（卡不可失去，无失效路径——与现有"拥有即永久"模型一致）。

## 2. 羁绊清单（每世界 3 组，共 9 组）

## 3. 与现有战力公式的衔接：**外乘系数方案（推荐）**

### 推荐方案
```
power = computePower(inventory) × (1 + min(Σ bondBonus, BOND_CAP))
```
`computePower` 内部逻辑（单卡 `rarWeight × (1+0.25×star)`、取 top5 求和）**一字不改**，在函数末尾追加一步外乘。

**理由**（相对"改公式/改单卡权重"方案）：
1. **改动面最小**：`power.js` 注释明确"三处必须同步"（web/core、服务端 power.ts、miniprogram），外乘只动三处各 1 行 + 新增一个纯函数 `bondBonus(inventory)`；改单卡权重则要重平衡全稀有度曲线。
2. **两轴独立可平衡**：升星是"单卡深度"（乘在单卡上），羁绊是"收集广度"（乘在总和上），外乘天然分离两个增长轴，数值调优互不牵连。
3. **排行榜零迁移**：`users.power` 仍是唯一排序字段，羁绊激活瞬间 power 跳升、榜单自然刷新，无需新字段、无历史数据回填。
4. 反对"加算进单卡"方案的理由：会与 top5 选卡逻辑纠缠（羁绊卡未必进 top5），出现"羁绊激活但编队不含该卡"的悖论。

### 实现注意
- `bondBonus(inventory)` 必须是 inventory 键集的**纯函数**（服务端/客户端同源常量表），不引入任何状态。
- 三处同源文件同步 + 单元测试对账（客户端预览值 = 服务端结算值）。

## 4. 数据模型

- **羁绊定义**：静态配置 JSON（`bonds-config.ts`，结构与 pools 同风格），键：`{ bondId, world, name, itemIds[], bonus }`。放配置不放 D1——羁绊是玩法规则而非运营内容，版本化随代码走（与 events-spec 的运营配置分离）。
- **激活状态**：**不落库**，由 `inventory` 实时推导（拥有即激活）。零迁移、零一致性风险。
- **展示数据**：`GET /api/bonds` 返回定义 + 当前激活态（服务端按用户 inventory 计算）。

## 5. 客户端 / 服务端分工

- **服务端**：`computePower` 升级版（含羁绊外乘）用于 draw/upgrade 结算写 `users.power`——**服务端重算是既有既定方向**（progression-spec §4"可改由云重算"），羁绊落地时一并切为服务端权威计算。
- **客户端**：同公式本地预览（图鉴页"激活后战力 +X"预览），以服务端返回 power 为准。

## 6. API 设计

### GET /api/bonds（authMiddleware）
```json
{ "bonds": [ { "bondId":"gs_yisheng", "world":"genshin", "name":"一心净土",
    "itemIds":["genshin_raiden","genshin_nahida","genshin_ayaka"],
    "bonus":0.05, "activated":true, "ownedCount":3 } ],
  "totalBonus": 0.10, "cap": 0.15 }
```
无 POST 端点——激活是拥有卡的推导结果，不存在"领羁绊"动作（也就无刷取面）。
power 相关端点（/api/draw、/api/upgrade）响应中的 `power` 字段自动携带羁绊后值，接口签名不变。

## 7. "冷门卡价值"改善论证

现状问题：power 只取 top5 单卡分 → R 卡（权重 10）在拥有几张 SR/UR 后**永久退出价值体系**，抽到 R 重复卡（5 碎片）近乎零反馈 → 抽卡体验塌陷在 R 区间（而 R 占各池 73%~94% 权重）。

羁绊的修复路径：
1. **R 卡获得编队外全局价值**：「尘世闲游」3 张 R 卡 = +2% 全局战力，等于给 R 卡一张 10 权重的"编队外席位"——收集 3 张 R 的边际战力收益 ≈ 半张 SR 进编队，但获取成本远低。
2. **抽卡反馈分层**：重复 R 仍是碎片（保底反馈），但"差一张温迪就能开羁绊"给 R 抽取增加了**目标感**，R 区间从纯噪音变成羁绊拼图。
3. **第二荣誉轴强化**（competitive-spec §5 的既定方向）：羁绊完成度与图鉴完成度同页展示，非数值玩家的收集成就有了战力背书。
4. **抽取决策多样化**：玩家为凑羁绊会主动去冷门池/冷门稀有度抽卡，缓解"只抽 UR 池"的单调主导策略（设计红线：主导策略——此为针对性解药）。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 羁绊加成推高 power 通胀，排行榜老玩家相对贬值 | 一次性跳变（非持续增长），且 cap 15% 封顶；赛季软重置（competitive-spec §4）本就为通胀兜底 |
| 三处同源公式漂移（客户端/服务端不一致） | bonds-config 作为第四个同源文件纳入"改公式三处同步"铁律注释；对账单测：固定 inventory 样例断言双端 power 相等 |
| 羁绊清单过强 → 变相逼抽指定池 | 单组 ≤5% 且组合含高稀有卡时收益被 cap 稀释；上线后监控各羁绊激活率，激活率 <5% 的组下版本调组合（配置级改动） |
| 玩家看不懂"为什么战力跳了" | 激活羁绊时弹一次性提示"羁绊『桃园结义』激活，战力 +3%"；power 详情页列出加成构成 |
