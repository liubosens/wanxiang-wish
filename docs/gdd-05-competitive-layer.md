# 万象心愿 · 战力 + 弱联机竞争层（v0.5 · 终版设计）

> 触发：用户回应 gdd-04 §6——"实际玩法没啥想法，战力数字体现吧，弱联机的排行榜，PK 啥的"。
> 结论：集齐后**不做分世界玩法**；统一用 战力 + 弱联机排行榜 + PK 作为竞争/社交保留层。Scope 保持受控。

## 1. 终版 Core Loop
```
抽卡(三机制) → 图鉴 → 升星/突破(养成黑洞)
   → 战力↑ → 排行榜/PK(弱联机竞争) → 排名/赛季奖励
   → 驱动更多抽卡/养成（无限）
```
收集是入口；**战力竞争是长线无限钩子**（排名不会满，段位不会满）。

## 2. 战力定义
- **账号战力** = 编队(最优 5 张) Σ `rarPower × (1 + 0.25 × 星)`。
- 升星/突破直接抬高战力 → 直接爬榜，闭环成立。
- [PLACEHOLDER]：编队手动/自动、是否含突破系数、是否分属性克制，待 playtest。

## 3. 弱联机排行榜 + PK
- **弱联机** = 异步、无实时连接：服务端存 战力 + 排名，玩家读榜/看好友；PK 自动结算。
- **PK** = 挑战相邻排名对手，战力 ±15% 方差自动结算；胜则换排名 + 小奖励（星砂/石头），负则记战绩。
- **排名只由战力决定**：PK 胜是资源事件 + 战绩，真正超排名靠升星抬战力——避免"赢了但榜不动"的割裂感。
- **赛季制**：每月结算发奖励并软重置，防战力通胀使排名失真（全员升星→榜通胀）。

## 4. 设计张力（呈现，不假装一致）
| 张力 | 处理 |
|------|------|
| 战力通胀使排名失真 | 赛季制 + 段位分组 |
| 泛休闲被高氪碾压 | 段位匹配 + 免战保护；PK 奖励为小资源**非硬通货**，避 pay-to-win 毒性 |
| 弱联机合规（微信） | 昵称/头像授权 [PLACEHOLDER]；排行榜需审核防刷 |
| 战力=唯一指标过裸 | 保留"图鉴完成度"作第二荣誉轴，避免纯数值焦虑 |

## 5. MVP Scope（终）
3 抽卡模块 + 图鉴 + 升星 + 战力聚合 + 弱联机排行榜/PK（原型内模拟 bots）。`prototype/paper-prototype.html` 已迭代到 v0.5。

## 6. 下一步 / 验证
- 跑 v0.5，观测：玩家是否因排名/PK **每天回来**；升星是否明显带动爬榜行为。
- 失败信号：① PK 参与率 <30% → 竞争层无感，回炉；② 榜顶被同一人长期霸占且无人追 → 需赛季/匹配。
- 通过 → 进 v1.0：接后端（云开发 DB 存战力/排名）+ 微信授权 + 真实赛季。
