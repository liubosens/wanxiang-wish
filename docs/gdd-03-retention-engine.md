# 万象心愿 · 保留引擎重设计（v0.3 — 基于原型实测反馈）

> 触发：用户跑 v0.2 原型后反馈——"太简略了，随便点点就全了，不耐玩"。
> 这是一次有效 playtest 结果，直接打在 P3 长期层缺位上。

## 0. 反馈 → 设计语言翻译
| 用户原话 | 设计归因 |
|----------|----------|
| 随便点点就全了 | 图鉴有限 + 每日按钮无冷却 + tuning 过松 → 收藏阶段太短 |
| 不耐玩 | 缺 P3 长期层，卡集完即无用，无"再开一次"动机 |
| 太简略 | 只有 P1+P2（收集+一抽），没把"卡牌有什么用"做出来 |

## 1. 根因诊断
P1「收集即脊梁」把**有限目标**当成了**长期钩子**——矛盾。收集必然结束，结束即流失。
真保留引擎必须**无限**，至少占两条：
- **养成（升星黑洞）**：同一批卡无限成长，成本指数增长 → 既是 sink 也是长线目标。
- **卡牌有用（试炼）**：集齐后卡牌=战力工具，决策从"抽"转移到"养/配"。
- **周期内容（banner）**：新题材/新卡持续注入（v0.4 再扩）。

## 2. 修正后的 Design Pillars（替换原 P1）
| # | Pillar | 玩家体验标准 |
|---|--------|--------------|
| P1' | 收集是入口不是终点 | 图鉴分"阶段完成(R/SR)"与"终极目标(UR)"两档；UR 仅 200 硬保底出 |
| P2 | 一抽即一回合 | 不变（已验证方向） |
| P3' | 卡牌必须有用 | 集齐后进「上阵试炼」，卡=战力工具，决策转移到养/配 |
| P4 | 概率透明 | 不变 |
| P5 | 穿越是皮不是核 | 不变；但"穿越不同模式"在 P3' 找到正经工作：试炼可换皮成各题材小玩法 |

## 3. 修正后的 Core Loop（补 P3'）
```
抽卡(星砂) → 图鉴(R/SR阶段完成, UR硬保底) 
   → 重复卡转碎片 + 试炼掉进阶石 
   → 升星(碎片+石头, 指数成本) 
   → 战力↑ → 打更高阶Boss(试炼) → 掉更多石头 
   → 更强升星 …（无限）
   ↘ 周期 banner 注入新 UR/新题材 → 收藏再燃
```
**关键转变**：玩家后期每天打开的理由从"抽新卡"变成"养满星 / 打过某 Boss / 等新 banner"。

## 4. Tuning 修正（治"随便点点就全了"）
| 项 | v0.2 | v0.3 | rationale |
|----|------|------|-----------|
| 每日星砂 | 无限可刷(+12) | 每日仅 1 次 +12，原型加"过一天"模拟，禁刷 | 资源稀缺才有决策 |
| UR 获取 | 普通池 8% | 移出普通池，仅 200 硬保底 | UR=终极目标，不能速通 |
| 升星成本 | 固定 120 | 10×(星+1)×稀有倍，且 ≥3 星需进阶石 | 指数黑洞，防通胀+长线 |
| Boss 阶梯 | 无 | 60/120/200/400 四档 | 给"养/配"明确目标 |

## 5. 原型 v0.3 已落地
文件：`prototype/paper-prototype.html`（覆盖 v0.2）
新增：稀有度门槛(UR锁)、升星(指数+石头)、上阵试炼(3 卡配队打 Boss)、每日冷却+"过一天"。
验证重点变为：**用户集齐 R/SR 后，是否愿意为打 Boss/升星继续每天来**——这条成立，保留引擎才成立。

## 6. 下一步
- 跑 v0.3，重点观测：R/SR 集齐后 24h 回访率、升星/试炼参与率。
- 若试炼参与低 → "卡牌有用"假设错，回炉 P3'（可能需换更轻的用途）。
- 若参与高 → 进 v0.4：接后端 + 真实掉率 + 首个月更 banner。
